# SECURITY.md

Модель угроз и реализованные контрмеры проекта `fitness-coach-bot`.
Документ соответствует требованиям раздела «Безопасность» стандарта
`UPTIME_STUDIO_QUALITY_STANDARD.md`. Живой документ — обновляется в том же PR,
что и код.

## Модель угроз

### Активы

| Актив | Где находится | Почему ценен |
|---|---|---|
| `BOT_TOKEN` | `.env`, не в git | полный контроль над ботом |
| Пароль админки | `.env` как PBKDF2-хеш | доступ к данным заявок |
| БД заявок | `data/database.db` | персональные данные клиентов (имя, возраст, контакт) |
| `SECRET_KEY` | `.env` | подпись сессий и CSRF-токенов |
| Список заявок в Telegram-уведомлениях | чат администратора | конфиденциальность |

### Актёры-злоумышленники

1. **Анонимный интернет-пользователь** — атакует веб-админку (brute-force логина,
   подбор сессий, XSS, SQL-инъекции, formula-injection в экспорт).
2. **Случайный пользователь Telegram** — шлёт произвольные сообщения боту,
   мусор в форму.
3. **Инсайдер с доступом к контейнеру/хосту** — кража секретов из окружения или
   файлов.

## Что защищено и как

### Секреты

- Ноль хардкода: токены/пароли/ключи только через переменные окружения
  (`app/config.py`, `admin/web.py`).
- Пароль админки хранится как PBKDF2-HMAC-SHA256 с солью и 600 000 итераций
  (`FLASK_PASSWORD_HASH`, формат без символа `$`, совместимый с docker-compose
  `env_file`) — не в открытом виде.
- `.env` и `.git` исключены из Docker-образа (`.dockerignore`) и из репозитория
  (`.gitignore`).
- В CI выполняется secrets-скан (`gitleaks`), при утечке секрета workflow падает.
- `SECRET_KEY` обязателен: без него Flask-приложение отказывается стартовать
  (`RuntimeError` — fail-closed).

### Веб-админка (Flask, порт 5004)

- **Аутентификация** — `login_required`, сравнение пароля через
  `hmac.compare_digest` (timing-safe, `admin/passwords.py::verify_password`).
- **Rate-limit** — `flask-limiter`: не более **5 POST на `/login` в минуту** на IP
  (`@limiter.limit("5 per minute", methods=["POST"])`).
- **Сессия** — cookie `HttpOnly`, `SameSite=Lax`, `Secure` по умолчанию
  (fail-closed: `True`, если не задано явно; `False` допускается только под
  локальный HTTP, см. `TECH_DEBT.md`).
- **CSRF** — per-session токен (`secrets.token_hex(32)`) + проверка
  `hmac.compare_digest` на всех мутирующих POST-эндпоинтах (`csrf_required`).
- **XSS** — шаблоны рендерятся через Jinja2 с автоэкранированием (`{{ }}`),
  пользовательский ввод в таблице экранируется.
- **HTTP-заголовки** — `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Cache-Control: no-store` (`@app.after_request`).

### Инъекции

- **SQL** — только параметризованные запросы (`?`-плейсхолдеры) во всех
  `execute()`: `app/handlers/trial.py::_save_application`, `admin/web.py`
  (index, update_status, delete, export). f-строки в SQL не используются.
- **HTML (Telegram)** — пользовательские данные экранируются `html.escape()`
  перед отправкой с `ParseMode.HTML` (`trial.py::_success_reply`, уведомление
  об ошибке).
- **Excel-формулы** — `sanitize_cell()` (admin/web.py) экранирует значения,
  начинающиеся с `=`, `+`, `-`, `@` (формула-инъекция → текст).

### Данные в Telegram

- Валидация ввода на каждом шаге формы (`validate_answer`): возраст — число
  1–100, контакт — телефон/@username, тексты — длиной 2–200 символов.
- Уведомления администратору и success-сообщение экранируют ввод пользователя.

### Docker

- Контейнер работает от непривилегированного пользователя `appuser` (uid 10001),
  `USER appuser` в `Dockerfile`.
- `.dockerignore` исключает `.env`, `.env.example`, `.git`, данные, бэкапы, логи.
- Только нужные порты проброшены наружу: 5004 (админка), 8001 (health).

### Защита данных

- WAL + `busy_timeout=5000` — целостность при конкурентной записи.
- Атомарные резервные копии через sqlite3 backup API (`scripts/backup.sh`),
  бэкапы `0600`, каталог `0700`, ротация 14 дней.
- Каталоги БД и логов монтируются отдельными volumes, `chown appuser`.

## Чего нет и что осознанно отложено

| Проблема | Статус | Где отслеживается |
|---|---|---|
| Админка отдаётся по HTTP без TLS | открыто | `TECH_DEBT.md` (план: Caddy/reverse proxy + `SESSION_COOKIE_SECURE=True`) |
| Хранилище rate-limiter'а — in-memory (не для multi-instance прода) | открыто | `TECH_DEBT.md` (при необходимости — Redis backend) |

## Процесс

- На каждый push/PR в `main` запускается `quality-gates.yml`: `bandit -r app admin -ll`
  (0 HIGH), secrets-скан gitleaks, coverage-гейт ≥ 80 %, модульность.
- Любое ослабление контрмеры — только через явную запись в `TECH_DEBT.md`
  с причиной и планом закрытия (правило стандарта: нет открытых исключений
  по разделам «Безопасность» без задокументированной причины).
