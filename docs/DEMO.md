# Как показать демо без открытого порта

## Принцип

Открытый порт опасен не сам по себе, а тем, что стоит за ним. Показывать нужно отдельный экземпляр с вымышленными данными, не рабочую БД и не сервер с другими секретами.

## Способ 1: скриншоты и запись экрана

Нулевой риск, подходит для постов и портфолио (см. раздел «Демо» в README).

## Способ 2: временный туннель на время показа

Сервер сам устанавливает исходящее соединение, входящий порт не открывается; ссылка работает по HTTPS и действует, пока туннель запущен. Пример команды для Cloudflare Quick Tunnel:

    cloudflared tunnel --url http://localhost:5004

`5004` — порт админки. Ссылка временная: после показа процесс останавливается. Актуальная документация: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/). Условия и лимиты сервиса здесь не описываются — смотрите документацию Cloudflare.

## Способ 3: отдельный хостинг для демо

Любой бесплатный или недорогой PaaS с Docker: демо-экземпляр живет отдельно от личного сервера и бота, данные вымышленные. Конкретные сервисы не рекламируются.

## Чего не делать

- Не публиковать порт рабочего экземпляра.
- Не использовать пароль, который где-то ещё применяется.
- Не оставлять туннель включенным.
